# AI Watch: registry release QA inventory

The release's claims are a primary institution/system dataset, source traceability, complete twelve-slot coding, usable exports and preservation of the earlier policy workflow. Test counts do not establish demand, source truth or national completeness.

## User-facing checks

- **Explorer**: eighteen named system rows; search by name, institution and assertion text; sector, documentary stage and attribution filters; combined filters; source-date sorting; filtered CSV; reset; explicit no-result state. Capture desktop/mobile and light/dark, including horizontal table scroll without page overflow.
- **Dossiers**: all eighteen routes, twelve accountability dimensions each, evidence disclosure with exact source URLs/dates/types, unknown-field message, typed observations, institution relationships, policies, downloadable Markdown and legacy links for six cases. Inspect e-Paarvai metrics, railway normative/causal limits, budget types and Digi Yatra chronological/retention context.
- **Data and method**: complete package, JSON, SQLite, schema, manifest/hash, analysis, every seventeen-table CSV, protocol/codebook/note/SQL, research logs, exclusions and source snapshots. Download actual bytes and compare to workspace hashes, not response status alone.
- **Regression**: supporting desk, policy comparisons/corrections, implementation ledger, earlier six service cases, complete old archive, source library and policy notebook import/export. New systems do not masquerade as old provision IDs.
- **Navigation**: primary entry and logo, all twelve rail destinations, keyboard controls, mobile nav strip, theme, deep links and source target URLs.

## Off-happy-path checks

- **Unavailable dataset**: intercept registry JSON failure, ensure visible error and retry recover without fabricated empty data.
- **Unknown identifier and empty filters**: provide explanatory non-census limit and a working return/reset control.
- **Binary downloads**: compare browser-downloaded ZIP and SQLite bytes against local originals; use the hosted bundle too.
- **Date/AI filters**: undated records last in source-date sort; qualified biometric/analytics contexts remain separately filterable, not silently excluded.

## Data and build checks

Primary-key uniqueness, foreign/generic evidence links, all assertion slots, metadata counts, source-date handling, clinical setting and specificity, specification/outcome distinction, amount types and lower-bound qualifiers, formula-neutralized CSV, source hashes/excerpt limits, dossier coverage, logs and rejected foreign validation. SQLite foreign keys/integrity and every ZIP manifest payload hash. Clean-checkout rebuild and deterministic archive comparison; production build and hosted preview workflows.
